# Ролики для лендинга

Короткие зацикленные ролики (до 10 с) для блоков Receive, Find, Ship. Снимаются в живом демо
https://warehouse.kaifparty.workers.dev/ и монтируются в Remotion.

## Как устроено
1. **Запись** — `node record-receive.mjs` (и `record-find.mjs`, `record-ship.mjs`). Playwright открывает демо в Chromium
   с `--force-device-scale-factor=2` и снимает кадры через screencast Chrome (2880×1800, ~50–60 к/с): `lib/capture.mjs`.
   Мышь движется плавно (`lib/director.mjs`), каждое событие пишется в `raw/<имя>.json`. Встроенная запись Playwright
   (`recordVideo`) не подходит: она 1x и 25 к/с.
2. **Монтаж** — `src/Clip.jsx` + `src/scenes/<имя>.js`: куски записи с разной скоростью, плавные приближения камеры,
   курсор, нарисованный по логу, растворение в первый кадр для бесшовного повтора.
3. **Рендер** — `node render.mjs Receive receive`: мастер 1920×1200 60 к/с, затем для сайта MP4 (H.264; WebM в Safari застывает на втором круге)
   шириной 1600 px без звука и постер JPEG → `out/`.

Перед рендером скопировать запись и лог в `public/` (так делают шаги выше: `cp raw/receive.mp4 raw/receive.json public/`
и первый кадр `public/receive-first.png`). Время в `src/scenes/*.js` — секунды сырой записи: после пересъёмки сверить
с логом (моменты кликов).

Нужно: Node, `npm install`, `npx playwright install chromium`, FFmpeg (Homebrew).

**Робот в кадре.** В демо робот добирается до коробки пользователя не сразу: в Receive около 100 с (коробка стоит в
очереди на ленте), в Ship около 30 с. Поэтому записи Receive и Ship длинные (`watchBox` в `lib/director.mjs` ждёт,
пока коробка не встанет на полку или не уедет на Dispatch, и пишет смены статуса в лог), а в монтаже они собраны из
кусков: у сегмента `cut: true` новый план растворяется поверх предыдущего за 0,3 с. Приезд, погрузка, поездка и
выгрузка идут в реальной скорости. (Сегмент с `rate` от 3 показал бы метку «N×» — сейчас таких нет.)

**Подписи и переходы.** У сегмента `caption` — подпись внизу слева (соседние сегменты с одинаковым текстом
показывают её одной плашкой). Переход `cut: true` — cross-zoom по мотивам GL Transitions: старый план
приближается и размывается, новый выходит из размытого приближения (0,5 с).

**Обложки.** `node render.mjs Receive receive 18.6` — третий аргумент: секунда ролика для обложки (говорящий кадр,
а не первый). Сейчас: Receive 18.6, Ship 16.6, Find 9.8, Hero 0. Пробный кадр: `node still.mjs Receive 11.2`.

**Шапка.** `node record-hero.mjs 36 clean` — медленный облёт склада для первого блока: `clean` прячет панели
приложения, подписи зон и подсветку при наведении, карта на весь кадр (заголовок лендинга лежит прямо на ней).
Чтобы карта была чёткой издалека:
- окно 1920×1200 при масштабе 1.5 (демо рисует 3D не больше чем в 1.5×) → 3D 2880 px один к одному;
- `steadyClock` в `openDemo`: ровный такт `requestAnimationFrame`, иначе демо под записью экрана считает кадры
  медленными и опускает разрешение 3D до 1× (в логе записи `ratioAtStart/ratioAtEnd` должны быть 1.5);
- коробки детальные на любом расстоянии: снимать с локальной копии сборки, где в бандле порог детализации
  `n=t<110?0:t<380?1:2` заменён на `n=t<1e9?0:t<380?1:2` (в `scene.js` это `NEAR=110`; сам репозиторий склада не трогать).
Курсор жмёт в середину склада (52.8 %, 62 % холста), камера на своём «домашнем» расстоянии (`zoom=N` — приблизить).
В `scenes/hero.js` один оборот 4.0 → 40.05 с (лучший SSIM), рендер Hero 2880×1800, для сайта
`node render.mjs Hero hero 0 2240 30` — 2240 px, ~7 МБ (2560/1920 при том же весе мутнее).

**Другая сборка демо.** `DEMO=http://localhost:8765/ node record-receive.mjs` снимает не живое демо, а локальную
сборку (например, ветку: `git archive origin/<ветка> locus-cloudflare | tar -x` и `python3 -m http.server 8765`).
После пересъёмки робот приезжает в другое время: сверить статусы в `raw/<имя>.json` и сдвинуть сегменты.
